# Contributing

Thank you for helping improve a NeKuDos public project.

## Before you begin

1. Read the target repository's README, license, and repository-specific contribution instructions.
2. Search existing issues and pull requests before opening a new one.
3. For a substantial behavior or API change, open an issue first so the scope can be discussed.
4. Report suspected vulnerabilities privately according to our [security policy](SECURITY.md).

## Preparing a change

- Keep the change focused and avoid unrelated refactoring.
- Preserve backward compatibility unless the change explicitly requires otherwise.
- Add or update tests when behavior changes.
- Update user-facing documentation when installation, configuration, inputs, outputs, or compatibility change.
- Never commit credentials, access tokens, private keys, personal data, customer information, or live SAP connection details.

## Pull requests

A pull request should explain:

- the problem being solved;
- the approach taken;
- how the change was tested;
- any compatibility or migration impact; and
- any follow-up work that remains.

By contributing, you agree that your contribution is provided under the license of the repository receiving it.
